# Governance

Osira API uses a lightweight, maintainer-led governance model while the project
is in early development.

## Roles

- **Contributors** improve the project through issues, documentation, code,
  reviews, and community support.
- **Maintainers** review and merge changes, manage releases and repository
  settings, handle security reports, and guide the project's technical
  direction.

Maintainer status is based on sustained, constructive participation, sound
technical judgment, and alignment with the Code of Conduct. Existing
maintainers decide additions or removals by consensus.

## Decisions

Routine decisions are made through issues and pull requests. Maintainers seek
rough consensus and consider security, user impact, compatibility,
maintainability, and project scope. When consensus cannot be reached, the
maintainers make and document the final decision.

Significant changes should begin with a public issue describing the problem,
alternatives, migration impact, and proposed design. Security-sensitive matters
follow the private process in [SECURITY.md](SECURITY.md).

This governance document may evolve as the contributor community grows.
